# Boat compact verifier

The normal upload is a single Lean file. The supervisor renders the reference from the admitted incumbent and submitted rational before running any candidate code. The source compiles against the narrow Main interface. A second isolated invocation imports its object with the compact RH implementation and exports four theorem roots. The checker receives only sealed export data. It compares target types and their definitions, audits axioms, and runs nanoda and Lean sequentially. An accepted receipt records both export hashes. Lean can cache the original axiom list in a compiled module, so diagnostic output from the elaborator cannot authorize a score.

To reproduce the worker on a fresh x86-64 Linux VM with systemd and Node 22, install the pinned toolchain and runtime using the two install scripts. Create separate unprivileged accounts named proofcheck and referee. Keep the checkout, installed runtime and prepared inputs in a readable supervisor-owned directory outside a home or temporary directory. Run prepare-job.sh and then run-job.sh as shown on the methodology page. RIEMANN_RECORDS_PATH selects the admitted records snapshot when replaying a historical submission. Each experiment starts from an empty workspace and a fresh receipt path.

build-runtime.sh rebuilds the cache from source. The compact GRH project and its Mathlib tree are pinned. zeta35.patch and LinearCombinationPrime.lean port the upstream Zeta23 proof scripts. LegacyFinsetSyntax.lean supplies the previous name for a product inequality. The reference uses the original counting definitions. The match runner calls the statement-comparison and axiom-check routines bundled with the pinned Lean release.
